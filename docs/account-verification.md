# 계정 동기화와 문항 정비 검증

검증일은 2026-10-17이다. 이번 변경은 인터넷보안 학습실만 대상으로 하며 WEB LAB·다른 앱·랭킹 서버는 변경하지 않았다. 아래 로컬/운영 API/공개 배포 확인을 구분한다.

로컬 최종 실행: Node **120/120**, 계정 UI **8/8**, 기존 Chromium/Firefox 화면 **각 25/25**, 배포 파일 39개 정적 검사 PASS. 깨끗한 `npm ci` 재설치·SDK 재빌드와 13개 주차 원고 재생성의 바이트 일치를 확인했다. npm 감사 보고 취약점은 0건이며 관리형 SDK 하위 패키지의 peer dependency/deprecation 경고는 남는다. 감사 보고 0건을 모든 보안 결함 부재로 해석하지 않는다.

## 확인한 입력

| 입력 | 상태 | 범위 |
| --- | --- | --- |
| architecture.md, README, 결정 기록, 콘텐츠 계약, 빌드·배포 설정 | VERIFIED | 해당 작업의 권한·구조·보존 규칙 전체 |
| 변경한 앱·도메인·저장·계정·DB·테스트 파일 | VERIFIED | 변경 코드와 직접 연결된 계약 |
| 13개 주차 JSON 및 교체 58문항 | VERIFIED | 전체 구조/연결 자동 검증, 교체 원문·새 보기별 해설 검토, 과거 정의 해시 대조 |
| 대형 part-1~4 원고 | PARTIAL | 목록과 생성 경로, 58개 교체 문항과 관련 정정 근거를 선택 검토. 전체 원고 재독으로 표현하지 않음 |
| 원본 PDF 13개 | NOT_INSPECTED | 이번 로그인·문항 정비 세션에서는 다시 읽지 않음. 최초 전체 범위 점검은 기존 source-inventory/verification 기록에 별도 보존 |

## 테스트 범위

| 층 | 검증한 사항 | 환경 |
| --- | --- | --- |
| 도메인·기록 | 병합, 동일 ID 재전송/내용 충돌, 필드 버전, 뒤늦은 승인, 초기화 epoch, 과대/손상 데이터, 역사 문항·북마크·시험 | Node 테스트 |
| 동기화 제어 | 응답 유실 후 재전송, 실제 큐 재로딩, 세션 사용자 변경, 첫 연결 실패 후 수동 재시도, 영구 검증 실패 정지, 다른 탭 쓰기 보존 | 메모리 저장소/전송 테스트 더블 |
| PostgreSQL | 미인증/미검증/타 계정 차단, private table 거부, RLS·RPC, 검증 한도, 모의고사 한 writer·takeover·만료·서버 채점, 계정 삭제 FK | PGlite 실제 PostgreSQL 엔진, Auth identity만 테스트 함수 |
| 계정 화면 | guest 보존·명시적 가져오기·로그아웃, 연결 재시도, 저장 거절 시 정답 완료 오표시 방지, 세션 누락·만료 안내, 손상 원본, 과거 북마크, 320px 라벨/넘침 | Chromium 8시나리오, Auth/API 대체 어댑터 |
| 기존 화면 | 학습·문제·시험·백업·충돌·보안 DOM·접근성·정정 비교 | 기존 25시나리오 브라우저 회귀 |
| 실제 Neon | 미인증 차단, managed 가입/OTP 검증, own RLS, A/B 계정 격리, 교대 JWT 8회, 직접 table 차단 | 운영 Auth/Data API, 이번 실행이 만든 테스트 계정만 사용 |
| 실제 두 브라우저 | 로그인·reload·진도 조회·오프라인 충돌 선택·모의고사 답안/마감 유지 takeover·제출 | 로컬 앱 + 운영 Neon, Chromium/Firefox 독립 컨텍스트 |
| 복구 API | 잘못된 OTP 거부, 제어된 OTP 확인, 비밀번호 변경 후 기존 비밀번호 거부 | 테스트 계정만, 실제 관리형 인증 API |

`tools/live-account-check.mjs`는 example.com의 고유 테스트 계정만 만든다. 인증 서비스가 생성한 해당 테스트 계정의 검증 레코드에 메모리 내 제어 OTP를 넣어 검증·복구 경로를 검사했다. 이는 실제 이메일 발송 성공이나 받은편지함 수신 검사가 아니다. 테스트 계정·검증 레코드를 정확한 ID/이메일로 삭제하고 잔여 0건을 확인했다. 실제 학습자 기록은 사용하지 않았다.

## 실패 재현 후 수정

| RED | 수정과 재검증 |
| --- | --- |
| DB jsonb 키 순서가 바뀐 동일 시도를 다른 내용으로 오인 | 키 순서와 무관한 canonical 비교, 동일 시도 재전송 PASS |
| 늦은 재시도 응답이 최신 필드 버전을 과거 의도에 부여 | 최초 승인 버전/큐 의존성 보존, 두 기기 충돌 회귀 PASS |
| 첫 계정 조회 실패 뒤 수동 동기화가 아무 것도 하지 않음 | 캐시 없는 시작 경로 재시도, 세션·브라우저 회귀 PASS |
| 무효 영구 요청이 계속 재시도됨 | 검증 오류는 큐를 보존하고 중단, 백업·재연결 UI PASS |
| 같은 ID의 다른 완료 시험을 조용히 무시 | 충돌 거부, 백업/병합 테스트 PASS |
| cold identity 초기화 시 운영 RPC AUTH_REQUIRED | invoker 초기화 wrapper, 권한은 유지, PGlite 재현 + 여러 신선한 운영 계정의 최초/교대 요청 PASS |
| retired 문항이 하나라도 있으면 유효한 새 시험도 INVALID_NEW_EXAM | 잘못 바인딩된 `id` JOIN을 명시적 컬럼 alias로 수정. inactive 포함 시험은 거부하고 active 시험은 허용, DB 및 운영 두 브라우저 PASS |
| 동기화가 차단되어 저장하지 못한 답안을 완료한 것처럼 표시 | 기록 반영을 확인한 뒤 feedback 전환, 계정 UI 회귀 PASS |
| 성공한 비밀번호 교환 뒤 세션이 없으면 이메일 미인증으로 안내 | 별도 세션 유지 실패 메시지와 다른 브라우저/백업 안내, 단위·UI 회귀 PASS |
| 자동 로그인 만료 때 guest 화면으로 조용히 돌아와 계정 기록과 혼동 가능 | 로그인 필요와 현재 보이는 guest 기록을 전역 배너로 구분, UI 회귀 PASS |
| 충돌 0건일 때 화면에 숫자 0이 불필요하게 표시 | 조건식을 boolean으로 평가, 캡처 점검과 DOM 회귀 PASS |
| 문항 교체가 과거 기록·북마크 ID를 없앰 | 58개 원래 정의 보존, 새 ID/alias, 과거 정답 해시·백업·시험 회귀 PASS |

테스트 도구의 대기 오류도 별도로 수정했다. 동기화 버튼을 누른 직후 과거 ‘마지막 동기화’ 문구를 완료로 오인하지 않도록 대상 상태 변화까지 기다린다. 이를 앱 오류 개수로 집계하지 않는다. 짧은 간격으로 운영 인증 검사를 반복했을 때 제공자가 429를 반환한 실행이 있었으며 제한을 우회하지 않았다.

## 공개 배포와 브라우저 호환성

로컬 Chromium/Firefox와 운영 Neon의 결합 검증은 통과했다. 로컬 WebKit에서는 비밀번호 교환 후 세션이 유지되지 않는 실패를 관찰했다. 공개 HTTPS에서의 브라우저 결과, 최종 CI run과 커밋은 배포 확인 후 아래에 기록한다. HTTP 로컬 결과만으로 모든 Safari 기기의 동작을 단정하지 않는다.

## 아직 검증하지 않은 범위

- 실제 이메일 받은편지함 수신·스팸 분류·지연·전송 한도 소진.
- iOS Safari/Android 실기기, 모든 브라우저 개인정보 보호 설정·확장 프로그램·스크린리더.
- 실제 60분 동안의 장시간 시험, 대규모 동시 사용자·장기간 무료 사용량, 제공자 전체 장애/복구.
- 비밀번호 복구 후 모든 과거 JWT의 즉시 무효화. 앱은 매 동기화 전 관리형 세션을 확인하지만 이미 발급된 JWT의 만료/취소 정책은 제공자 경계다.
- 실제 시험의 문제·배점·교수님 채점 기준 또는 학습 성과. 631문항과 테스트 통과가 합격 보장은 아니다.

계정 기능이 실패해도 기존 guest 기록과 내보내기는 유지한다. 인증 우회·브라우저 추적 방지 해제·Web Storage에 세션 토큰 보관으로 호환성 문제를 숨기지 않는다.
