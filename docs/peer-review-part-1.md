## 초기 문제와 해결

1. **관련 없는 오답 — 해결.** 초기 회귀 검사가 검출한 정확한 문항/보기는 `w01-q017/b`, `w02-q020/c`, `w02-q025/b,c,d`, `w02-q040/b`, `w02-q057/b`, `w03-q011/d`, `w03-q021/b`, `w03-q023/b,d`, `w03-q046/c`, `w03-q049/c`, `w04-q010/a`, `w04-q016/c`, `w04-q020/b`의 16곳이다. 글꼴·배경색·화면 픽셀·디스크 용량 같은 범주 이탈을 개념 혼동으로 교체했다. 이 목록 이외의 지나치게 쉬운 오답도 수동 검토하여 함께 개선했다.
2. **키 교체 진단 — 해결.** `w02-q057`의 오답 세 개는 글꼴·ARPANET 연대·도메인 길이여서 키 수명주기 이해를 측정하지 못했다. 이전 암호문이 새 키로 자동 복호화된다는 오해, 복원 수단의 조기 폐기, 인증서 유효성과 복호화 능력의 혼동으로 교체했다. 문제문은 여러 장애 원인을 추측하는 대신 다음 교체 작업의 적절한 요구를 고르게 했다.
3. **CPS 보기 — 해결.** `w02-q065`의 CipherPacketSize·ComputerPortSwitch 같은 무관한 약어를 PKI 정책·발급·운영 관행의 혼동으로 교체했다. 정답인 Certification Practice Statement는 유지했다. 기존 `w02-correction-13`에 RFC 3647을 추가하여 교안 02주차 26쪽의 명칭 정정 근거를 직접 보강했다.
4. **IKE 버전 경계 — 해결.** `w04-ike`와 `w04-correction-05`에 연결된 교안 04주차 13–15쪽 설명을 검토했다. IKEv2의 첫 CHILD_SA는 보통 IKE_AUTH에서 설정되며, 뒤의 CREATE_CHILD_SA만으로 처음 생성된다고 읽히면 안 된다. IKEv2의 SA 수명은 양 끝점이 같은 값으로 협상하는 것이 아니라 각자 로컬 정책으로 집행한다. 본문·사례 단계·정정 기록을 고치고 도입 이유의 무조건적인 “키 수명에 합의”도 제거했다. 관련 문항 `w04-q026`–`w04-q030`의 기존 정답 자체가 틀렸다는 판정은 아니다.
5. **문제문과 선행 설명 — 해결.** `w02-q011`은 공개 IV·솔트와의 구분이 분명하도록 대칭 암호의 공유 비밀이라는 조건을 넣었다. `w01-q034`의 단방향·반이중·전이중 구분을 연결 목표의 본문에 추가하고 ACK·재전송·기밀성과 혼동하지 않게 했다. `w01-q024`처럼 “단정할 수 없는 것”을 묻는 문제는 나머지 세 보기가 실제로 참인 대조 항목이 되도록 확인했다.

## 방문한 1차 근거

아래 명세·공식 문서의 관련 절을 확인했다. 문서 전체 완독이나 모든 과거 통계의 독립 입증을 뜻하지 않는다.

- [RFC 7296 §1.2](https://www.rfc-editor.org/rfc/rfc7296.html#section-1.2): IKE_AUTH의 인증과 보통 첫 Child SA 생성. [§2.8](https://www.rfc-editor.org/rfc/rfc7296.html#section-2.8): IKEv2 수명은 협상하지 않으며 각 끝점이 정책을 집행하고 필요 시 갱신한다. 위 IKE 정정의 직접 근거다.
- [RFC 3647 §1.2 및 §3.4](https://www.rfc-editor.org/rfc/rfc3647.html): Certificate Policy와 Certification Practice Statement의 명칭·역할 차이. `w02-q065`와 `w02-correction-13`의 직접 근거다.
- [RFC 4302](https://www.rfc-editor.org/rfc/rfc4302.html), [RFC 4303 §3.1](https://www.rfc-editor.org/rfc/rfc4303.html#section-3.1): AH의 인증/무결성과 ESP의 보호 범위, 전송/터널 모드, 내부·외부 IP 헤더의 구분을 대조했다. 전송 모드를 TCP/UDP에만 가능한 것으로 가르치지 않는다.
- [NIST FIPS 197](https://csrc.nist.gov/pubs/fips/197/final): AES의 블록·키 크기와 라운드 구분. [NIST FIPS 186-5](https://csrc.nist.gov/pubs/fips/186-5/final): DSS는 서명 표준이며 특정 알고리즘 이름 하나와 동일하지 않다는 구분을 대조했다.
- [systemd 프로젝트 FAQ](https://systemd.io/FAQ/): SysV runlevel과 현대 target의 관계를 대조하여 교안의 옛 부팅 설명을 모든 배포판의 현행 동작으로 일반화하지 않았다.

## RED → 수정 → GREEN

수정 전 실제 파일을 대상으로 회귀 검사를 먼저 실행했다.

- 최초 5개 검사: PASS 2 / FAIL 3. 무관 오답 검사, `w02-q057`의 키 교체 범위 검사, `w02-q065`의 CPS 보기 범위 검사가 실패했다.
- IKE 검사를 추가한 상태: PASS 5 / FAIL 1. 첫 CHILD_SA 설명 누락을 검출한 뒤 본문과 정정을 수정했다.
- 최종 점검에서 같은 IKE 검사에 도입 이유 일관성을 추가: PASS 5 / FAIL 1. “키 수명에 합의”가 남은 것을 검출하여 버전별 키 갱신 정책 확인으로 수정했다. 검사 수는 6개로 유지했다.
- 최종 재생성: `node tools/authoring/part-1.mjs`. 담당 네 파일 각각 `validateWeek()` 통과. 목표별 최소 세 문항, 문항/family 중복 없음, 문항 페이지의 목표 소속, 전체 페이지 coverage의 누락·중복 없음 확인.
- 최종 검사: `node --test --test-reporter=spec test/content-part1-regression.test.js test/content.test.js`. **22개 PASS / 0 FAIL**. 이 중 Part1 전용은 6개다. 나머지는 기존 전체 콘텐츠 구조 검사이며 다른 주차의 의미를 이 작업자가 새로 심사했다는 뜻은 아니다.
- 최종 담당 파일의 UTF-8 무BOM·CRLF·대체문자 없음, JSON 네 보기 문구 고유성, 보고서의 개인 절대경로 없음도 확인했다.

자동 검사는 금지 표현·특정 회귀·연결 구조를 검출한다. 모든 오답의 의미적 유일성을 자동 증명하지 않으므로 수동 읽기와 구분한다. 전체 앱 테스트·브라우저·CI·배포는 이 작업의 완료 근거가 아니며 부모가 담당한다.

## 수정 결정과 파일

직접 JSON만 수정하는 방식과 원고에 명시적인 교체 목록을 두는 방식을 비교했다. 재생성 시 개선이 사라지지 않도록 후자를 선택했다. 원고의 `peerDistractors`는 기존 ID마다 독립 작성한 오답 세 개와 각각의 이유를 적용하는 빌드 단계 데이터다. 기존 초안 뒤에 적용되며 런타임 템플릿·새 문항 생성·수량 증식이 아니다. 향후 수정도 해당 교체 목록과 회귀 검사를 함께 확인해야 한다. 아키텍처·접근통제·저장 정책의 변경은 없다.
